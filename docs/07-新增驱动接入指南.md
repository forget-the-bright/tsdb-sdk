# 新增驱动接入指南

> 适用：为 tsdb-sdk 增加一个新的工业时序数据库驱动（如力控 pSpace），或把已有厂商 SDK 包进公共接入层。
>
> 目标：新驱动只写“厂商差异”，不重复公共层；接入后公共接口、配置切换、原生逃生口、测试方式都与现有 HLS/GE/IoTDB 驱动一致。

## 1. 先判断接入方式

| 厂商提供 | 推荐方式 | 代价 | 备注 |
|---|---|---|---|
| REST / HTTP API | 公共层 `HttpTransport`（Hutool） | 低 | 与现有 HLS/GE/IoTDB 一致；需要协议文档与测试环境 |
| JDBC 驱动 | `java.sql` + 厂商 JDBC jar | 中 | 需要驱动类、URL、账号、表/视图模型；注意 SQL 注入与连接池 |
| Java API（jar） | 直接依赖 jar，包一层 | 中 | 需要 Maven 坐标或本地 `system`/私服；注意静态单例与线程安全 |
| C/C++ SDK（DLL/.so） | JNI 桥接 | 高 | 需要本地库、平台矩阵、JVM crash 隔离；不建议作为一期 |
| OPC UA/DA | 不在本期范围 | — | 现场明确不做 OPC 接入 |

**原则**：能用 REST 就不用 JDBC，能用 JDBC 就不用 JNI；JNI 只作为最后手段，并且必须单独进程隔离。

## 2. 模块骨架

新增模块 `tsdb-sdk-<vendor>`，目录与现有驱动一致（`tsdb-sdk-iotdb` 是最完整的样板）：

```text
tsdb-sdk-<vendor>/
  pom.xml
  README.md                        # 目录树 + 「按任务找类」表
  src/main/java/io/github/forget_the_bright/tsdb/<vendor>/
    package-info.java              # 公共入口清单 + 协议要点 + 子包导航
    <Vendor>Client.java            # 门户：只做装配与分派，不写业务算法
    <Vendor>Config.java            # 配置校验，不依赖 Spring、不发网络请求
    <Vendor>Driver.java            # SPI 入口
    <Vendor>Mapper.java            # 厂商模型 -> 公共模型（公共层，留根包）
    internal/
      package-info.java
      <Vendor>HttpClient.java      # 或 JdbcClient / NativeBridge
      <Vendor>Models.java          # 厂商 DTO <-> 公共模型换算
      <Vendor>NativeApi.java       # 原生逃生口，能力不裁剪
      <Vendor>TokenManager.java    # 需要令牌时
      adapter/
        package-info.java
        <Vendor>Support.java       # 共享配置/客户端/开闭状态/异常上下文
        <Vendor>TagCatalogAdapter.java
        <Vendor>CurrentValueAdapter.java
        <Vendor>HistoryAdapter.java
        <Vendor>DeltaAdapter.java
        <Vendor>WriteAdapter.java  # 支持写入时
    nativeapi/                     # 端点枚举或请求 DTO（按需）
      package-info.java
  src/main/resources/META-INF/services/
    io.github.forget_the_bright.tsdb.common.spi.TsdbDriver
  src/test/java/.../<vendor>/      # 单测镜像主代码包路径
    it/                            # 门控只读集成测试（-D<vendor>.it=true）
```

父 `pom.xml` 的 `<modules>` 增加该模块，`tsdb-sdk-bom` 的 `dependencyManagement` 增加该模块。

### 2.1 包布局约定（强制）

这套布局的目的只有一个：**开发者按「我要改什么」就能定位到包**，同时宿主应用的 import
只落在根包与 `common.api`/`common.model`。现行包地图见
[`docs/03` §4](03-总体架构与模块设计.md)。

1. **根包只放公共入口**：`Client`/`Config`/`Driver`/`Mapper` 与驱动枚举（如 `IotdbTransport`）。
   适配器、`Support`、序列组装器一律放 `internal/adapter`，**不得平铺在根包**。
2. **`internal.adapter` 的类是 `public final`，但不是公共 API**。Java 没有 `internal` 可见性，
   门户跨包构造它们只能放宽到 `public`。因此必须三处同时声明：每个类 Javadoc 首段写
   「<b>非公共 API</b>：门户装配层实现，签名随内部重构变化，宿主应用请勿直接依赖」、
   包 `package-info.java` 再声明一次、`docs/04` §11.2 登记这次可见性放宽。
3. **只放宽跨包真正被调用的成员**：全部构造器（门户 `new`）+ 门户直接调用的方法
   （现有例子只有 `GeSupport.unsupported`、`HlsSupport.ensureOpen`）。`Support` 的其余访问器、
   组装器的方法，调用方都在同批下沉的类里，**保持 package-private**，不要顺手全开。
4. **职责包按需拆，不预建**：一个包混了两种以上职责、或类数明显偏多时才拆
   （IoTDB 拆成 `internal/sql`、`internal/query`、`internal/transport`）。
   不为「将来可能有的职责」建空包，也不要造只有 1–2 个类的碎片包。
5. **包私有簇必须整簇同包**：互相引用的 package-private 类拆到不同包会直接编译失败。
   拆包前逐类 grep 调用方，确认跨包引用只指向 `public` 类；否则整簇一起移动。
6. **每个包都要有 `package-info.java`**：职责一句话 + 可见性契约 +
   **本包类清单与「改什么找哪个类」** + 依赖方向，中文，带 `@since`。
   跨包 `{@link}` 只能指向 `public` 类型，包私有类用 `{@code}`，否则 javadoc 解析不到。
7. **依赖方向**：`adapter → 实现职责包 → 共享工具`。根包门户 ↔ `internal.adapter`
   的双向引用是门面模式的固有形状，可以接受；但**驱动之间不得互相依赖，common 不得依赖驱动**。
8. **共享工具先复用**：HTTP 用 `common.internal.http.HttpTransport`（Hutool），
   JSON 用 `common.internal.json.Json`/`JsonText`（fastjson，仅树解析），
   文本用 `common.internal.Texts`。不要在驱动里再写一套。
9. **测试镜像包路径**：单测与被测类同包（这样才能测包私有成员）；门控只读 IT 放 `<vendor>.it`，
   凭据只写进 `.gitignore` 排除的 `*-it.properties`，不入库、不打印。

## 3. 实现 SPI

```java
public final class FooDriver implements TsdbDriver {
    @Override public String type() { return "foo"; }
    @Override public Set<Capability> capabilities() { return CapabilitySet.of(...); }
    @Override public void validate(TsdbInstanceConfig config) { new FooConfig("validate", config, permissiveSecurity()); }
    @Override public TsdbClient create(TsdbInstanceConfig config, DriverContext context) {
        FooConfig cfg = new FooConfig(context.getInstanceName(), config, context.getRootConfig().getSecurity());
        return new FooClient(cfg, new FooNativeApi(cfg));
    }
}
```

约束：

- `type()` 必须与 YAML 的 `type:` 完全一致，小写、无空格。
- `validate` 只做结构与安全校验；不要在 `validate` 里发网络请求。
- `create` 不负责重试；连接失败直接抛 `TsdbConnectionException` / `TsdbAuthenticationException`。
- 驱动内部不要使用静态可变字段；每个实例持有自己的配置、token、连接。
- `META-INF/services/...TsdbDriver` 文件内容写全限定类名；`ServiceLoader` 依赖它。

## 4. 声明能力，不要“假统一”

`Capability` 是业务选择接口的依据。只声明真正支持的能力；不支持的方法必须在客户端抛 `TsdbUnsupportedException`，而不是返回空集合。

| 能力 | 对应接口 | 说明 |
|---|---|---|
| `TAG_BROWSE` | `TagCatalog.listTags/getTag` | 标签目录；不支持过滤就在客户端过滤或拒绝 |
| `CURRENT_VALUE` | `CurrentValueReader.read` | 实时值/最后值 |
| `RAW_HISTORY` | `HistoryReader` + `QueryMode.RAW` | 原始点 |
| `AGGREGATED_HISTORY` | `HistoryReader` + `QueryMode.AGGREGATED` | 区间聚合 |
| `INTERPOLATED_HISTORY` | `HistoryReader` + `QueryMode.INTERPOLATED` | 插值 |
| `SAMPLED_HISTORY` | `HistoryReader` + `QueryMode.SAMPLED` | 采样 |
| `TREND` | `HistoryReader` + `QueryMode.TREND` | 趋势 |
| `WRITE` | `WriteSession.write` | 写入；必须同时受 `security.allow-write` 控制 |

## 5. 映射规则

### 5.1 质量码

厂商质量码必须映射到 `Quality`，原始码放 `Sample.vendorQualityCode`：

| 厂商语义 | 公共 Quality |
|---|---|
| Good | `GOOD` |
| Uncertain / Questionable | `UNCERTAIN` |
| Bad / Failed | `BAD` |
| Stale / Timeout | `STALE` |
| 厂商未提供 | `UNKNOWN`（禁止猜 `GOOD`） |

HLS 的 `OneTagHDBValue` 没有 `Quality_AVG`，因此 AVG 质量必须是 `UNKNOWN`，并在 `TagSeries.attributes["qualitySource"]="hls_not_provided"` 标注。新驱动遇到“部分列没有质量码”时照此处理。

### 5.2 值类型

`ValueType` 只有 `DOUBLE/LONG/BOOLEAN/STRING/BYTES/UNKNOWN`。厂商 `DataType` 映射不确定时，先按字符串内容推断（整数→LONG、小数→DOUBLE、true/false→BOOLEAN），仍不确定就 `STRING`；不要为了“看起来正确”强行转 double。

### 5.3 时间

- 公共模型统一 `Instant`（绝对时刻），区间语义 `[start, end)`。
- 所有驱动都必须接入公共 `TimeConfig`，并在客户端暴露 `timeConfig()`、`parseTimestamp(String)`、`formatTimestamp(Instant)`；即使协议只用 epoch、当前用不上，也要保留这套能力。
- 厂商返回本地时间文本时，无时区文本按 `time.response.source-zone` 解析，默认 UTC，不假设 `+08:00`；现场是东八区就显式配 `GMT+8`。
- 厂商返回秒/毫秒时间戳时，按数量级判断（> 1e11 视为毫秒），并写测试；协议是 epoch 的驱动不消费 `request.*`，但展示仍走 `target-zone/pattern`。
- 构造 `Sample` 后调用 `withTimeFormat(timeConfig)`，让返回对象同时带 `timestampDate` 与 `timestampText`；前端可直接展示文本。健康检查结果同样用 `HealthStatus.withTimeFormat(...)` 补齐。

### 5.4 标签

- `TagInfo.name` 用厂商的稳定标识（HLS `TagName`、GE 标签名、IoTDB 完整路径）。
- `description` 放厂商描述/别名；`vendorType` 放原始类型；额外字段放 `attributes`。
- 公共层不做标签名重写；业务侧需要统一命名时在适配层做映射。

## 6. 查询语义

| 公共查询 | 厂商实现建议 |
|---|---|
| `RAW` | 原始点查询，按 `Direction` 排序，`maxPoints+1` 探测截断 |
| `AGGREGATED` | 厂商聚合接口；`Aggregation` 映射到厂商枚举/函数 |
| `INTERPOLATED` | 厂商插值接口；无此能力就抛 `UNSUPPORTED` |
| `SAMPLED` | 厂商采样接口；无此能力就抛 `UNSUPPORTED` |
| `TREND` | 厂商趋势接口；无此能力就抛 `UNSUPPORTED` |

统一规则：

- 返回顺序与请求标签顺序一致；缺失标签返回 `TagSample(tag, null)`，不要静默丢掉。
- 超过 `maxPoints` 截断，并设置 `TagSeries.truncated=true`。
- 聚合请求没有 `aggregation`、区间没有 `interval` 时，在客户端参数校验阶段拒绝。
- `partialResultAllowed=false` 时，任一标签失败就抛 `TsdbQueryException`；为 `true` 时把厂商错误写入 `attributes`。

## 7. 原生逃生口

每个驱动提供 `internal/<Vendor>NativeApi`，由 `<Vendor>Client.unwrap` 暴露：

```java
FooNativeApi nativeApi = client.unwrap(FooNativeApi.class);
```

原生 API 要求：

- 实例方法，不用静态单例。
- 不改变公共层状态；调用方自担厂商语义。
- 返回厂商原始对象或驱动自己的轻量 DTO；不要让厂商类型泄漏到 common。
- 至少覆盖：标签列表、实时值、原始历史、聚合历史、健康检查；写入按厂商能力提供。

## 8. 配置与安全

```yaml
tsdb:
  default-instance: foo_main
  security:
    allow-write: false
    allow-insecure-transport: false
    verify-hostname: true
    audit-enabled: true
  instances:
    foo_main:
      type: foo
      protocol: rest          # rest | jdbc | sdk
      base-url: https://10.0.0.10:8443
      auth:
        username: ${FOO_USER}
        password: ${FOO_PASSWORD}
      timeout:
        connect-ms: 5000
        read-ms: 30000
      retry:
        max-attempts: 2
        backoff-ms: 200
      options:
        path-prefix: /api/v1
```

安全要求：

- 默认 `allow-write=false`；写入必须显式开启，并在驱动内检查。
- 默认拒绝明文 HTTP；现场只有 HTTP 时，必须显式 `allow-insecure-transport=true`，启动 WARN 并记录审计。
- 凭据只从环境变量/密钥管理注入，不写进仓库；`tsdb.yml` 已在 `.gitignore`。
- 所有拼进 SQL/URL 的标识符必须校验或参数化；IoTDB 驱动的分工可直接参考：位号文本的解析、
  节点白名单与引号规范化只在 `IotdbTagPath` 一处完成，`IotdbSql` 不再接受裸字符串路径、
  只保留 `SHOW TIMESERIES` 掩码白名单与间隔字面量校验。
- Token 刷新必须单飞（synchronized 双检），401 只清一次并重试一次，避免风暴。

## 9. 测试要求

最低测试集（参考 `HlsClientTest` / `GeClientTest` / `IotdbClientTest`）：

1. 能力声明与“不支持的方法抛 `TsdbUnsupportedException`”。
2. 认证头/Token 刷新；401 重试一次。
3. 标签列表：过滤、分页、`getTag` 精确匹配。
4. 实时值：顺序一致、类型映射、质量映射、缺失返回 null。
5. 原始历史：时间区间、排序、limit/截断。
6. 聚合历史：聚合枚举映射、interval 单位。
7. 写入：默认禁用；开启后请求体/参数正确。
8. 安全：默认拒绝明文 HTTP；非法路径/掩码被拒绝。
9. `unwrap` 返回原生 API 并可调用。
10. 健康检查：成功/失败映射。

测试不要连真实生产库；用 JDK `com.sun.net.httpserver.HttpServer` 模拟协议，或用厂商提供的测试容器。涉及时间/时区的用例必须固定时区。

## 10. 力控 pSpace 接入预案

已确认（公开资料）：

- pSpace 提供 C / .NET / Java / Node.js / Web API / ODBC / JDBC / OLEDB 接口。
- 支持 OPC HDA 1.20 数据处理、22 种统计查询、插入/替换/删除/按时间段删除。
- 单机 500 万点、读写峰值 100 万条/秒；集群 3000 万点。

仍需现场/厂商确认（决定驱动形态）：

1. Java API 的 jar 名称、Maven 坐标/私服地址、入口类与初始化方式。
2. JDBC 驱动类名、URL 格式、认证方式、表/视图模型（标签表、历史表、实时表）。
3. REST/Web API 的端口、路径、鉴权、请求/响应示例。
4. 是否必须安装 pSpace 客户端/配置 DSN；是否支持 Linux。
5. 标签命名规则、质量码、时间精度、聚合函数清单。
6. 写入权限与审计要求；是否允许 SDK 写 DCS。
7. 测试环境、账号、示例点位。
8. 许可与再分发限制（驱动 jar 能否随 SDK 发布）。

在拿到 1–4 之前，不创建“空壳驱动”；先把 `docs/06` 的问卷发给厂商，拿到接口文档后按本指南实现。
