## 2. 为什么要做这套 SDK

不是为了“再包一层 REST”，而是解决采购与运维风险：

1. 现场时序库由业主/集成商采购，厂商可能不配合提供接口文档、不保证兼容升级；
2. 业务代码如果直接依赖厂商 SDK，更换厂商时要重写采集、查询、报警、报表逻辑；
3. 统一 SDK 把“厂商差异”关进驱动，把“业务语义”留在公共层；
4. 更换厂商时，理想情况只改：依赖的驱动 jar、`tsdb.yml` 的 `type` 与连接参数；
5. 厂商特有能力不被阉割：公共接口覆盖 80% 通用场景，剩余 20% 用原生 API 逃生口。

**核心权衡**：可用性（现场能稳定读、断线能恢复）与安全性（只读优先、凭证外置、TLS、审计）。功能数量不是第一目标。

## 4. 单实例策略切换

### 4.1 运行模型

```text
业务代码
   │  只依赖 TsdbClient
   ▼
TsdbManager（策略门面，持有唯一活动客户端）
   │  type 选择驱动
   ├── HlsClient ── HLS REST
   ├── GeClient ─── GE REST
   ├── ForceControlClient ── pSpace（待定）
   └── IotdbClient ── IoTDB REST v2
```

- `tsdb.default-instance` 指定启动时启用的实例；
- `manager.client()` 懒加载该实例；
- `manager.switchTo("fc_main")`：先创建新客户端，成功后再关闭旧客户端；失败则保留旧客户端；
- 同一时刻只保持一个厂商连接，避免现场“多套库并存”带来的配置、网络、许可复杂度；
- 每个 `TsdbClient` 仍是独立实例（token、超时、重试、配置各自持有），为将来多实例留出空间，但**默认不启用**。

### 4.2 切换边界

| 场景 | 是否支持 | 说明 |
|---|---|---|
| 改配置重启后换库 | ✅ | 改 `default-instance` 即可 |
| 运行中 `switchTo` 换库 | ✅ | 公共接口不中断调用方代码；切换瞬间的请求需调用方处理失败 |
| 同一查询跨两个库联邦 | ❌ | 不在本期范围；如需要，由上层编排 |
| 双写/迁移 | ❌ | 本期不做；避免写 DCS 的安全风险 |
| 多实例同时在线 | ❌（默认） | 架构保留能力，但不作为现场运行模式 |

### 4.3 业务代码约束

- 业务代码只注入/持有 `TsdbClient`，不持有具体驱动类；
- 需要厂商特有能力时，显式 `unwrap`，并在代码中标注“厂商绑定”；
- 切换后能力可能变化，调用前用 `capabilities()` 判断；
- 不要在启动时缓存 `TagInfo` 跨库复用：标签命名、类型、质量码语义均可能不同。

## 5. 力控 pSpace 接入（已落地）

### 5.1 结论

pSpace 走官方 **Web API（REST/JSON）**，不依赖 DLL/JNI：模块 `tsdb-sdk-pspace`，
驱动 `type = "pspace"`，覆盖目录、当前值、原始历史、聚合、插值、采样、差分与写入，
原生 23 个 REST 端点 + 8081 WebSocket 订阅全部保留在 `unwrap(PspaceNativeApi.class)`。
详细端点映射、类型/质量表与验证口径见 **docs/16-pSpace接入与验证.md**。

### 5.2 手册 + 7.1 实测协议事实

| 项 | 事实 |
|---|---|
| 读接口方法 | 手册写 GET，但现场 7.1 对 GET 一律返回 `[CREST]<GET> ... Parse Json data failed`；**全部读接口改为 POST + JSON 请求体**，字段与查询参数同名 |
| 响应外层 | `{code,mesg,data}` 信封；`code=0` 成功；**`code=1` 表示“范围内无数据”并附空 `data`**，按空结果处理；其它码（含 -1）抛 `TsdbQueryException` 并带厂商码 |
| 字符集 | 手册允许 GBK/UTF-8；现场无论传什么，实际都按 GBK 收发。驱动 `options.pspace.charset` 默认 `gbk`，请求体/响应/参数统一同一种编码 |
| tagids / tagnames | 互斥，同时出现以 tagids 为准；tagids 支持 `1,2,3`、`1-4`、`1,2,3,5-10` |
| fields / fieldnames | 互斥；7.1 只接受 `fieldnames`，数字 `fields` 报 `property id not exist`，驱动一律只用 fieldnames |
| archived | `1=zlib` 本期不支持：配置或调用出现即抛 `TsdbUnsupportedException`，不静默降级 |
| 分页 | 请求 `pagesize`+`pagenumber`，响应 `{total, page:{count=总页数, number, size, values[]}}`；按 `page.count` 翻页。`/PointPage` 分页生效；`/PointFilter` 实测**忽略**分页参数，一次返回全部匹配 |
| 缓存未热 | 刚启动时目录只返回根节点、`/PointChildren` 报 `Not find children`、`/RealData` 报 `No Valid Data`。厂商确认解法：先 **POST `/Refresh`（body `{}`）** 再查。驱动内建自动刷新（见 5.4） |
| 质量码 | `192` 好 / `0` 坏，其余按 `UNCERTAIN` 并保留 `vendorQualityCode`；手册无码表，192 只是缺省约定 |
| 时间 | `yyyy-MM-dd HH:mm:ss[.SSS]`，含 `24:00:00`（次日 00:00）；解析失败抛 `TsdbDataException`，不兜底当前时间 |
| 聚合间隔 | `interval` 单位是**秒**；`avg/minim/maxim/total/count/range/delta/intve/orgintve` 输出桶起点，`staval`/`endval` 输出桶内真实采样时刻 |
| 聚合函数 | `avg/minim/maxim/total/count/staval/endval/range/delta/intve/orgintve`；`INTERPOLATED→intve`、`SAMPLED→orgintve` |
| 目录 | 7.1 `/PointPage` 实测 35 点（31 tag + 4 目录节点），`TagType` 0/1/2…，`DataType` 1…16，字段含 `EngUnit`、`His_IsSave` |
| **模拟环境聚合响应** | 7.1 对**有数据桶**正常返回 `pv`，**只有空桶**返回 `{"tm":...,"qy":0}` 且不含 `pv`。10 分钟稠密窗口内 `avg` 的 `pv` 与同桶原始点均值逐位一致（如 10:58 `50.711094`）；24h×3600s 仅 3 个非空桶，曾是“厂商不返回 `pv`”误判的来源。7.1 只读 IT 已用同窗口原始点核对 AVG、`endval` 与差分 |
| 插值前提 | 数字化点（`TagType=1`）在本窗口内 `intve` 返回 `code=1`（无可插值数据）；模拟量点（`TagType=2`）正常返回桶数 |
| 鉴权 | REST 无客户端鉴权，账号在服务端 ini；配置了 `auth` 会校验失败并提示，避免误以为鉴权生效 |
| 订阅 | 8081 WebSocket，请求同 `/RealData`；仅原生 `PspaceNativeApi.subscribe(...)`，不进入公共 API |

### 5.3 模块结构与配置

```text
tsdb-sdk-pspace/
  src/main/java/io/github/forget_the_bright/tsdb/pspace/
    PspaceDriver.java            // type = "pspace" + 能力声明 + 配置校验
    PspaceClient.java            // TsdbClient 门户：tagCatalog/currentValues/history/deltaHistory/writeSession
    PspaceConfig.java            // 字符集、分页、自动刷新、时间默认值
    internal/
      PspaceNativeApi.java       // 23 个 REST 端点 + withAutoRefresh + subscribe
      PspaceResponseParser.java  // 点位/实时/历史/分页解析（包内可见）
      PspaceSubscription.java    // java.net.http.WebSocket（8081）
      PspaceHttp.java            // 信封/裸数据兼容、code=1、archived=1 拒绝、GBK
      PspaceModels.java / PspaceMapper.java / PspaceTagResolver.java
    internal/adapter/            // PspaceSupport + 5 个 Pspace*Adapter（非公共 API）
```

```yaml
tsdb:
  default-instance: pspace_main
  instances:
    pspace_main:
      type: pspace
      base-url: http://172.16.176.14:8080
      timeout:
        connect-ms: 5000
        read-ms: 30000
      options:
        pspace:
          charset: gbk                    # gbk | utf-8
          page-size: 1000
          auto-refresh: true              # 读路径取空/缓存未热时自动 POST /Refresh 重试一次
          refresh-min-interval-ms: 1000   # 两次自动刷新的最小间隔
          archived: 0                     # 只接受 0；1 直接校验失败
      time:
        request:
          pattern: "yyyy-MM-dd HH:mm:ss.SSS"
          zone: GMT+8
        response:
          source-zone: GMT+8
          pattern: "yyyy-MM-dd HH:mm:ss.SSS"
```

### 5.4 能力、自动刷新与限制

声明能力：`TAG_BROWSE`、`TAG_SEARCH`、`CURRENT_VALUE`、`AGGREGATED_HISTORY`、
`INTERPOLATED_HISTORY`、`SAMPLED_HISTORY`、`CUMULATIVE_DELTA`、`WRITE`（原始历史为基线能力）。
不声明：`TAG_CRUD`（建/改/删点走原生）、`TREND`、历史删除、报警订阅。

自动 `/Refresh`：目录/点位查询为空、`getTag` 解析不到、`/RealData` 为空或命中
`Not find children` / `No Valid Data` 时，若 `auto-refresh=true`，刷新一次并重试原请求
一次；由 `refresh-min-interval-ms` 限速，不做全局锁、不循环刷新。写路径仅在位号解析时
允许触发；建点/删点/改点与 `probe()`/`create()` 不自动刷新。

明确不支持（调用即抛 `TsdbUnsupportedException`）：`archived=1`、`TREND`、
聚合间隔非整秒、`FillPolicy` 非 `NONE`（插值/采样/差分）、日历月粒度差分、未知聚合函数。

已知语义缺口（**未执行，不声称已验证**）：
- 聚合数值与**力控趋势客户端**显示值的一致性：未执行；本次只验证“聚合值与同窗口原始点自洽”；
- `/UpdRealData` 是否落历史未确认（造数 IT 已就绪，环境现有点位时按约定跳过）；
- `AddPoint` 字段集与 `DelPoint` 可用性未现场确认。

非 RAW 空桶（服务端只返回 `tm`/`qy=0`、无 `pv`）不进入 `TagSeries` 样本列表，
改由 `valueMissingReason` / `valueMissingCount` / `valueMissingFirstAt` /
`valueMissingLastAt` / `valueMissingAll` 属性诊断；RAW 的 null 值仍为 `Sample.ofNull`。

### 5.5 安全要求

- 默认只读；写能力需 `security.allow-write=true` 且单独凭证；
- 优先 HTTPS/TLS；现场只有 HTTP 时必须经 TLS 代理，并显式 `allow-insecure-transport=true`（启动 WARN + 审计）；
- 凭证只从环境变量/密钥管理注入，不落配置文件；
- DCS 侧账号最小权限，禁止使用管理员账号；
- 所有写操作记录审计日志（谁、何时、哪个标签、什么值、结果）；
- 集成测试双重门禁：`-Dpspace.it=true` 只读；写/造数另加 `-Dpspace.it.allow-write=true`，
  且 base URL 主机必须属于 {127.0.0.1, localhost, 172.16.176.14}；**现有点位优先，探测到可用点位就不建点**。

## 8. 验收标准（现行）

### 8.1 公共层

- [x] 同一套 `TsdbClient` 接口可操作 HLS、GE、IoTDB 与 pSpace；
- [x] 质量码归一：HLS 0/1、GE 0/1/2/3 均映射到统一 `Quality`；
- [x] 时间统一 `Instant`，区间 `[start,end)`；
- [x] 不支持的能力抛 `TsdbUnsupportedException`，不静默降级；
- [x] 原生 API 可通过 `unwrap` 调用；
- [x] YAML 配置 + 环境变量占位符；
- [x] 单活动实例 + `switchTo` 关闭旧连接。

### 8.2 力控 pSpace（7.1 模拟环境实测）

- [x] 能列出标签：`/Refresh` 后 `/PointPage` 返回 35 点（31 tag + 4 目录节点）；
- [x] 能读实时值：5 个位号 `/RealData` 全部有值，顺序与入参一致；
- [x] 能读历史：`/HistData` 24h 原始 200 点（按 `maxPoints` 截断）；
- [x] 聚合/插值能力按实际接口声明：AVG / INTVE / ORGINTVE 均按窗口返回桶；数字量点 `intve` 返回 `code=1` 按空结果处理；
- [x] 断线/超时快速失败并可重试（`readPost` 仅对超时/连接失败重试）；
- [x] 只读账号无法写入（`security.allow-write=false` 时 `isWritable()=false`）；
- [x] 聚合数值与同窗口原始点自洽：AVG 9 桶、差分 9/10 桶已对数（容差 1e-3）；
- [ ] 聚合数值与 pSpace 趋势客户端一致：**未执行**——需现场趋势对照；
- [ ] 100 个标签实时值延迟对比：**未执行**——模拟环境仅 31 tag；
- [ ] 写入链路（`/UpdRealData` 落历史、`/AddPoint`、`/DelPoint`）：**未执行**——环境已有点位，按约定不造数；
- [ ] 《力控 pSpace 接入 POC 报告》待现场数据补齐后成文。

### 8.3 无缝切换

- [ ] 同一段业务代码，仅改 `tsdb.yml` 的 `default-instance`，即可从 HLS 切到 GE（已验证接口层）；
- [ ] 切换后标签目录、当前值、区间聚合的返回结构一致；
- [ ] 驱动缺失/配置错误时启动失败并给出可操作错误信息；
- [ ] 切换失败时旧客户端仍可用（`switchTo` 先开新后关旧）。
