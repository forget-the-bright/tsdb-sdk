## 2. 为什么要做这套 SDK

不是为了“再包一层 REST”，而是解决采购与运维风险：

1. 现场时序库由业主/集成商采购，厂商可能不配合提供接口文档、不保证兼容升级；
2. 业务代码如果直接依赖厂商 SDK，更换厂商时要重写采集、查询、报警、报表逻辑；
3. 统一 SDK 把“厂商差异”关进驱动，把“业务语义”留在公共层；
4. 更换厂商时，理想情况只改：依赖的驱动 jar、`tsdb.yml` 的 `type` 与连接参数；
5. 厂商特有能力不被阉割：公共接口覆盖 80% 通用场景，剩余 20% 用原生 API 逃生口。

**核心权衡**：可用性（现场能稳定读、断线能恢复）与安全性（只读优先、凭证外置、TLS、审计）。功能数量不是第一目标。

## 4. 单实例策略切换

### 4.1 运行模型

```text
业务代码
   │  只依赖 TsdbClient
   ▼
TsdbManager（策略门面，持有唯一活动客户端）
   │  type 选择驱动
   ├── HlsClient ── HLS REST
   ├── GeClient ─── GE REST
   ├── ForceControlClient ── pSpace（待定）
   └── IotdbClient ── IoTDB REST v2
```

- `tsdb.default-instance` 指定启动时启用的实例；
- `manager.client()` 懒加载该实例；
- `manager.switchTo("fc_main")`：先创建新客户端，成功后再关闭旧客户端；失败则保留旧客户端；
- 同一时刻只保持一个厂商连接，避免现场“多套库并存”带来的配置、网络、许可复杂度；
- 每个 `TsdbClient` 仍是独立实例（token、超时、重试、配置各自持有），为将来多实例留出空间，但**默认不启用**。

### 4.2 切换边界

| 场景 | 是否支持 | 说明 |
|---|---|---|
| 改配置重启后换库 | ✅ | 改 `default-instance` 即可 |
| 运行中 `switchTo` 换库 | ✅ | 公共接口不中断调用方代码；切换瞬间的请求需调用方处理失败 |
| 同一查询跨两个库联邦 | ❌ | 不在本期范围；如需要，由上层编排 |
| 双写/迁移 | ❌ | 本期不做；避免写 DCS 的安全风险 |
| 多实例同时在线 | ❌（默认） | 架构保留能力，但不作为现场运行模式 |

### 4.3 业务代码约束

- 业务代码只注入/持有 `TsdbClient`，不持有具体驱动类；
- 需要厂商特有能力时，显式 `unwrap`，并在代码中标注“厂商绑定”；
- 切换后能力可能变化，调用前用 `capabilities()` 判断；
- 不要在启动时缓存 `TagInfo` 跨库复用：标签命名、类型、质量码语义均可能不同。

## 5. 力控 pSpace 接入

### 5.1 已确认事实（公开资料）

- 力控 pSpace 是企业级实时/历史数据库，覆盖 Windows、麒麟、UOS、方德、CentOS，支持 x86/ARM/MIPS/LoongArch；
- 官方称提供标准化 API/SDK，支持 RESTful、MQTT、OPC DA、OPC UA；
- 官方产品页明确具备 **C API / .NET API / Java API / Python API / Web API / ODBC / JDBC / OLEDB** 多种二次开发接口；
- 可与 Oracle、SQL Server、MySQL、人大金仓、达梦等关系库集成；
- 公开资料未给出 Java SDK 的包名、Maven 坐标、REST 路径与鉴权细节；
- 检索到 pSpace 6.0.1.9 开发支持包含 32/64 位 API 库、头文件与 C# 测试工程，推断底层以 C/C++ DLL 为主，Java API 可能为 JNI 封装或独立 jar；
- TDengine 企业版 pSpace 连接器通过“服务器地址 + 端口 + 用户名/密码”接入，支持历史查询、实时订阅、查询同步三种采集模式；点位使用 `\Beijing\Chaoyang\...` 形式的 LongName 路径，并带质量列。这说明 pSpace 存在服务端网络接口，但协议细节未公开。

> 以上仅为公开资料，不能替代现场版本确认。

### 5.2 待现场确认（POC 前必须回答）

1. 现场 pSpace 的具体版本、授权模块（实时/历史/报警/计算）；
2. 是否启用 REST 服务？端口、基路径、认证方式（Basic/Token/自定义）、TLS；
3. REST 是否覆盖：标签目录、实时值、原始历史、区间聚合、插值、写入；实时值是轮询最后值，还是必须用订阅接口；
4. 若走厂商 SDK：是 C/C++ DLL 还是 .NET？是否提供 Java/JNI 封装？是否支持 64 位与目标 OS；
5. 是否必须安装 pSpace 客户端/采集器？应用机与 pSpace 服务器的网络端口；
6. 标签命名规则、类型系统、质量码定义、时间戳精度/时区；
7. 单次查询标签数/点数上限、并发限制、超时行为；
8. 只读账号是否可用；是否允许写入（默认禁止）；
9. 是否有测试环境、测试标签、对比工具（pSpace 趋势/报表）；
10. 许可是否允许第三方 SDK 直连，是否有 NDA/接口文档获取流程。

### 5.3 驱动设计（预留，待 POC 定稿）

```text
tsdb-sdk-forcecontrol/
  src/main/java/io/github/forget_the_bright/tsdb/forcecontrol/
    ForceControlDriver.java      // type = "forcecontrol"
    ForceControlClient.java      // 公共接口实现
    ForceControlConfig.java      // base-url / auth / protocol / options
    internal/
      ForceControlNativeApi.java // 原生逃生口
      ForceControlRestClient.java // 若 REST 可用
      ForceControlJniBridge.java  // 若只能走厂商 DLL（可选）
      ForceControlModels.java
      ForceControlMapper.java
```

配置草案：

```yaml
tsdb:
  default-instance: fc_main
  instances:
    fc_main:
      type: forcecontrol
      protocol: rest          # rest | sdk，POC 后确定
      base-url: https://10.20.1.10:port
      auth:
        mode: basic
        username: ${FC_USER}
        password: ${FC_PASSWORD}
      timeout:
        connect-ms: 5000
        read-ms: 30000
      options:
        api-prefix: /pspace
        verify-hostname: true
```

能力声明必须“宁缺毋滥”：POC 确认一项才声明一项，未确认的能力默认不声明，调用时抛 `TsdbUnsupportedException`。

### 5.4 安全要求

- 默认只读；写能力需 `security.allow-write=true` 且单独凭证；
- 优先 HTTPS/TLS；现场只有 HTTP 时必须经 TLS 代理，并显式 `allow-insecure-transport=true`（启动 WARN + 审计）；
- 凭证只从环境变量/密钥管理注入，不落配置文件；
- DCS 侧账号最小权限，禁止使用管理员账号；
- 所有写操作记录审计日志（谁、何时、哪个标签、什么值、结果）。

## 8. 验收标准（现行）

### 8.1 公共层

- [x] 同一套 `TsdbClient` 接口可操作 HLS、GE 与 IoTDB；
- [x] 质量码归一：HLS 0/1、GE 0/1/2/3 均映射到统一 `Quality`；
- [x] 时间统一 `Instant`，区间 `[start,end)`；
- [x] 不支持的能力抛 `TsdbUnsupportedException`，不静默降级；
- [x] 原生 API 可通过 `unwrap` 调用；
- [x] YAML 配置 + 环境变量占位符；
- [x] 单活动实例 + `switchTo` 关闭旧连接。

### 8.2 力控（POC 通过条件）

- [ ] 能列出指定前缀的标签；
- [ ] 能读 100 个标签的实时值，延迟与 pSpace 客户端一致；
- [ ] 能读 24h 原始历史，点数/值与 pSpace 趋势一致；
- [ ] 聚合/插值能力按实际接口声明，不伪装；
- [ ] 断线/超时快速失败并可重试；
- [ ] 只读账号无法写入；
- [ ] 形成《力控 pSpace 接入 POC 报告》（版本、协议、端口、鉴权、标签、性能、限制）。

### 8.3 无缝切换

- [ ] 同一段业务代码，仅改 `tsdb.yml` 的 `default-instance`，即可从 HLS 切到 GE（已验证接口层）；
- [ ] 切换后标签目录、当前值、区间聚合的返回结构一致；
- [ ] 驱动缺失/配置错误时启动失败并给出可操作错误信息；
- [ ] 切换失败时旧客户端仍可用（`switchTo` 先开新后关旧）。

## 10. 一句话总结

**用一套公共接入层锁住业务语义，用独立驱动隔离厂商差异，用单实例策略降低现场复杂度；力控先行 POC，IoTDB 随后，横河本期不做。**
